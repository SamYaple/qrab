# qapi-spec-parser

A code generation tool that parses QEMU's [QAPI schema](https://www.qemu.org/docs/master/devel/qapi-code-gen.html) and produces Rust type definitions. The generated output is the source for the sibling `qapi` crate.

## Usage

```sh
cargo run -p qapi-spec-parser -- vendor/qemu > projects/qapi/src/lib.rs
```

The tool takes a path to a QEMU source tree and writes generated Rust code to stdout. Redirect it to `projects/qapi/src/lib.rs` to update the autogenerated crate.

Tested with QEMU versions up to v9.1.0 (version support table covers v1.1.0 through v10.2.0).

## How it works

The parser operates in three stages:

### 1. Parsing

Uses [nom](https://crates.io/crates/nom) to parse QEMU's QAPI JSON-like schema files. The entry point recursively follows `include` directives to read the full schema. Parsed tokens include:

- **Enums** -- enumeration types
- **Structs** -- structured data types
- **Unions** -- discriminated (tagged) unions
- **Alternates** -- untagged union types
- **Commands** -- QMP command definitions
- **Events** -- asynchronous event definitions

### 2. Intermediate representation

Parsed QAPI types are converted to an IR that maps cleanly to Rust constructs:

- QAPI types become `Struct` or `Enum` IR nodes
- Type names are converted to PascalCase, field names to snake_case
- QAPI primitive types are mapped to Rust types (`str` -> `String`, `int` -> `i64`, `bool` -> `bool`, etc.)
- Struct inheritance (via `base`) is resolved by copying fields from the base type
- Unions produce both a struct (with discriminator + data field) and an enum for the branches
- Optional fields become `Option<T>`, array fields become `Vec<T>`

### 3. Code generation

Uses [quote](https://crates.io/crates/quote) and [prettyplease](https://crates.io/crates/prettyplease) to produce formatted Rust source. Generated types are annotated with `#[qapi(...)]` attributes carrying metadata such as version info (`since`), wire-format names, and conditional compilation hints.
